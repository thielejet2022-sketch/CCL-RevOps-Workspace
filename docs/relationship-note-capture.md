# Relationship note capture
Implemented storage and manual assistant procedure — 2026-10-12.
This is JET's personal preparation workflow, not an adopted CCL organizational process.

## User instruction
JET may simply say: “Add this detail about [person]: [information]” or “Research [person/topic] and add it.”
EVA resolves the existing People record and records the detail without requiring field-by-field input.

## Procedure
1. Read the current Airtable schema and match the person by full name or verified email. Create a People entry only when no matching person exists. Ask only for genuinely ambiguous identities.
2. Read that person's linked notes to avoid duplicates. Separate distinct enduring facts from dated events.
3. For user-supplied information, record REPORTED by JET and the capture date. Do not imply the person told JET directly unless stated.
4. When research is requested, verify sources and distinguish KNOWN public evidence from unresolved claims. Do not assign Reported by person to public research. Use Evidence State and Source; leave speaker classification blank when inapplicable.
5. Retain a complete understandable Detail, relevant evidence excerpt or clearly labeled paraphrase, source title/date/URL or recording ID, attribution caveats, and capture timestamp. A disappearing source must not erase the captured information.
6. Shared On means when information was communicated by the person; leave blank for public research when that date is unknown. Put source publication/retrieval dates in Source. Never substitute retrieval date for a call date.
7. Use Current/Historical/Superseded/Needs clarification. Retain earlier evidence rather than silently replacing history. Preserve unknown ages, birthdays, outcomes and dates.
8. Add a natural optional Follow-up Prompt and refresh the manually curated People summaries.
9. Read back write results. Report what was added, unresolved claims and the record link.
